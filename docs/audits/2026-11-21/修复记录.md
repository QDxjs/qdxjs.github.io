## 已实施的修复

| 编号 | 修复内容 | 验收依据 |
| --- | --- | --- |
| D01 请求完成时写入已脱离页面的旧节点 | 用请求对象标识当前请求；完成回调重新取得有效节点。停用时先使请求失效再 abort，迟到的成功、失败、超时回调均不能恢复已停用的组件。 | VM 覆盖成功、错误、超时、无效 JSON，在节点移除、整页 body 替换、观察器尚未执行、停用后的完成回调；浏览器验证真实 DOM 替换与迟到响应。 |
| D02 SPA 监听器生命周期不完整 | 监听稳定的 documentElement 子树，覆盖 body 整体替换；统一由 applyConfigChange 管理创建、停用和重新启用，同时清理计时器，避免重复监听及定时任务。 | 覆盖启动时禁用、站点排除后启用、body 替换、多次开关、停用断开监听和请求取消；真实 MutationObserver 验证通过。 |
| D03 设置保存与重载的校验不一致 | 数字配置共享边界规则。保存前完成全部校验，使用原生输入有效性提示；无效输入不会修改运行配置或写入 GM 存储。刷新间隔只接受 0–3600 的整数。 | 覆盖负数、超范围、小数、空值、非有限数及无效字符串；0 与 3600 可保存，重新启动并打开设置后不变。其他数值控件与加载规则同步；保留原有有限 z-index 值兼容性。 |
| D04 搜索高亮对比度不足 | 仅将搜索结果 mark 的文字改为主题正文色 --ink，保留原有强调色 18% 背景及整体配色。 | CSS 计算回归及浏览器 computed style 验证；浅色与深色、普通与悬停状态均高于 4.5:1。 |
| D05 正文链接只用颜色区分 | 为 .prose a 添加持续可见的下划线；沿用已有链接颜色和焦点样式。 | 样式回归及实际文章页面 computed text-decoration-line 检查通过。 |
| R01 旧依赖审计告警 | Astro 从 4.16.19 升到 7.4.13，RSS 使用 4.0.19；同步处理内容加载和 Zod API 迁移，更新锁文件中的易受影响依赖。没有使用 --force 或绕过审计。 | 锁文件干净安装成功；最终 npm audit 的 low/moderate/high/critical/total 全部为 0，见 npm-audit-after.json。 |
| R02 缺少发布前校验 | 加入类型诊断、VM/CSS 回归、静态产物检查和桌面/移动 Chromium 测试。PR 与 main 使用相同校验；PR 不部署，main 全部通过后才上传 Pages 并进入部署作业。 | 本地完整命令通过；GitHub Actions 配置已完成，远端执行结果另见 Actions 运行记录。 |

## Astro 迁移与兼容性

- 将旧 `src/content/config.ts` 移到 `src/content.config.ts`，三个集合使用官方 glob loader。
- 使用 loader 的 `id` 生成文章地址，以 `render(entry)` 渲染正文；已有 frontmatter slug 保留。
- 新增 `tests/fixtures/published-routes.json`，对升级前的 13 个文章入口逐项校验，防止编译成功但已发布地址改变。
- 保留 RSS 只收录 notes 和 essays 的原有策略，以及 sitemap、搜索索引、canonical 和本地链接结构。
- 类型检查发现旧 Hitokoto 组件存在隐式类型和可空节点问题，补充最小类型与空值保护，使其纳入同一检查门禁；未重新启用该组件或调整站点布局。

## 后续维护和发布

操作说明见项目 [README](../../../README.md)。常规改动执行 `npm run verify`，随后运行 `npm run test:browser` 与依赖审计。Linux CI 已配置自动安装 Chromium 系统依赖。

GitHub Actions 仅在 main 非 PR 运行且 build 作业全部成功后部署；Pages 写权限和 OIDC 权限仅授予 deploy 作业。上述本地验收命令不会触发该流程；main 分支推送后由 Actions 执行发布。发布后仍需检查实际域名、Pages 设置、静态资源与下载脚本，并观察真实外部服务、字体和网络条件下的行为。

浏览器测试使用 Chromium 桌面和 Pixel 7 移动模拟，外部资源请求被阻止；Hitokoto API 和 GM 存储采用可控测试桩。尚未进行 Firefox、WebKit、真实手机和用户脚本管理器扩展矩阵测试，也未重新测量线上 Core Web Vitals。

原报告中依赖真实内容决策或线上测量的建议（例如演示内容替换、真实访客性能及 SEO 效果）仍属于可选后续工作；本次没有据此删除内容、重做页面或更换字体服务。
