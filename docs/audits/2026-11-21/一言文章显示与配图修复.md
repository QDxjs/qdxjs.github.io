# 一言文章显示与配图修复

日期：2026-11-21（Asia/Singapore）

## 问题与原因

用户反馈《一言 · 全站通用版》的部分代码块和代码文字难以辨认，并且文章缺少使用示意图。

在本地构建页面的 Chromium 中复现了两处样式冲突：

- Astro 默认 Shiki 深色高亮输出的背景为 `rgb(36, 41, 46)`，浅色主题下仍然生效；博客的 `.prose pre code` 却将文字覆盖为浅色主题正文色 `rgb(42, 37, 32)`，造成深底深字。
- `pre` 的 `.85rem` 与内部 `code` 的 `.86em` 叠加，实际代码字号只有 **11.696 px**。

## 修复

1. 在 `astro.config.mjs` 中配置 Shiki 的 `github-light-default` / `github-dark-default` 双主题，并关闭固定默认色。
2. 在文章范围内依据博客现有 `data-theme` 切换代码块与高亮 token 的前景、背景和文字样式，保留语法高亮。
3. 代码块字号调整为 `.875rem`（默认根字号下为 **14 px**），内部 `code` 继承字号，避免再次缩小；行内代码也设置 14 px 下限。
4. 长行在代码框内部横向滚动，避免撑宽手机页面。
5. 给文章补充三张实际脚本界面截图：悬浮栏效果、内容与外观设置、站点匹配设置。每张均有替代文本、说明、明确尺寸和原图链接，采用懒加载；设置面板截图按自然尺寸显示，不放大。

## 配图来源与复现

执行：

```sh
node scripts/capture-hitokoto.mjs
```

截图工具使用仓库中的 2.4 版用户脚本，在 Playwright Chromium 的离线演示页中实际渲染。按用户补充要求，背景改为米色纯色（`#F4EFE3`），不再使用博客简介或其他带文字的页面。截图前断言演示页没有正文文字和背景图片，注入脚本后断言不存在额外内容节点，防止后续重新生成时再次带入占位介绍。用户脚本管理器的 GM 接口由演示适配器提供；句子固定为“把网页的一角，留给一句话。”，不依赖第三方接口的实时返回。

演示域名为保留示例域名 `demo.example`，没有访问该域名的外部服务。悬浮栏示例使用底部位置和 18 px 字号，文章说明了默认安装位置为顶部。截图不是用户脚本管理器扩展安装流程的验证。

图片位于 `public/images/works/hitokoto/`：`bar-solid.jpg`、`settings.png`、`sites.png`，合计约 **163 KiB**。原图按 2 倍像素密度生成，文章声明正确的宽高比以预留布局空间。悬浮栏效果图裁去多余留白，展示尺寸为 900 × 220；使用新文件名避免沿用旧背景图片的缓存。
